The stack, the GitHub setup, the skills in our Claude Code system, and the design system itself. Everything here is read out of the live repo, not written from memory.

What it is

matviykorsunskiy.me/dialbridge-report is the free Lost Job Report. A contractor types their business name, answers four questions, and watches a live seven step scan build a scored audit of their Google presence. Two scores are free; the rest unlocks behind a phone verification.

Build

The stack

Seven files. No React, no Tailwind, no bundler, no npm install. The whole page is static assets plus fetch calls.

index.html256 lines. Markup and nothing else. styles.css1,693 lines. Every token and component. app.js372. Search, autocomplete, picking the business. questions.js172. The four question popup. scan.js1,033. The seven step scan and all Google calls. engine.js1,134. Scoring, the money maths, the heat map. report.js1,359. Rendering, the gate, the blueprint form.

Why no framework

The reader is a contractor on a phone, often on bad signal, and the page has to paint before they lose interest. A framework adds a few hundred kilobytes and a build step to a page that renders a handful of components.

What runs where

1

Browser

Google Places API for the business, the competitors and the nine point ranking grid. Google Static Maps for the heat map image. All the scoring maths.

2

n8n

Anything needing a secret or a server: OTP send and verify, the LLM keyword picker, fetching the contractor page source which a browser cannot read cross-origin, Brave search for a missing website, and every write to GHL.

3

GoHighLevel

CRM, contact records, tags, and the outbound text and email.

Rule of thumb: if it needs a key the user must not see, it is an n8n webhook. If it only needs the public Maps key, it stays in the browser and costs nothing to run.

Four things the workflow does

01

Writes config.js from repository secrets

The Maps key and all eight n8n webhook URLs are GitHub secrets, printed into a config.js at build time. config.js is gitignored and config.example.js is the committed template, so no key has ever been in a commit.

02

Copies the site and the PDF

The seven source files plus the blueprint folder, so the lead magnet PDF has a real public URL to email.

03

Touches .nojekyll

Without it Pages runs Jekyll and silently drops anything starting with an underscore.

04

Cache-busts every asset

Appends the commit SHA and run number to every script and stylesheet, so nobody is ever running yesterday JavaScript against today HTML.

Set or change a secret

gh secret set GOOGLE_MAPS_API_KEY --repo matkors/dialbridge-report

Tooling

The build loop

This is the part most setups skip, and it is the reason the page works. Nothing ships on the strength of looking right in the editor.

01

Drive the real page in a real browser

Playwright loads the actual files, runs the actual flow and screenshots at 390px and 1280px. Every layout claim in this document was checked that way.

02

Measure, do not eyeball

Read getBoundingClientRect and compare against the budget. That is how the overflowing cards, the clipped dialog and the wrapped headings were all caught before anyone saw them.

03

Run the whole funnel against production

Search, pick, answer, scan, gate, unlock, email. End to end on the live site, watching every webhook response.

04

Spoof the user agent when testing live

Our n8n webhooks have ignoreBots on, and headless Chromium announces itself as HeadlessChrome. Without a normal user agent every call returns 403 and it looks exactly like an outage. This cost a full debugging cycle.

The rule behind all four

If a claim can be checked, check it. The report tells contractors things about their own business, so anything we cannot verify does not go on the page, and anything we cannot verify about the page does not get pushed.

The one colour rule

Orange is action. Green, amber and red are verdicts about the business. Never let a verdict colour a button, and never let orange imply something is good or bad. The moment those mix, a red card reads as a thing to click.

The part that matters

Interaction rules

These are the decisions that made the scanner work, and they transfer to the new site more usefully than any hex value.

01

One question per screen

Four questions, four taps, one idea each, no scrolling and no form. A contractor answers it at a red light. A single page with four fields would not get finished.

02

Earn the wait, do not hide it

The scan shows seven named steps completing in real time, because it really is calling Google seven ways. Showing the work is what makes the result feel measured rather than generated. A spinner would have wasted the same thirty seconds and bought nothing.

03

Give the proof away, gate the explanation

The two scores are free and visible. Everything under them is blurred, not hidden. The blur is the point: it proves there is something there, which is what makes a phone number feel worth giving.

04

Never show a number you cannot defend

When Google cannot return a service-area business, the page explains why instead of drawing nine "not found" pins. A confident wrong answer costs more trust than an honest gap.

05

Their words, not ours

"Your Google Maps position when someone searched plumber", not "SERP grid ranking". And money is always a monthly figure. Never ask the reader to do arithmetic to feel the point.

06

The logo goes home

Small thing, constantly got wrong. The brand mark is a real button that resets the scan, with a visible back control beside it for anyone who does not think to try the logo.

Focus is visible, always

Every interactive element gets outline: 3px solid var(--focus); outline-offset: 3px on :focus-visible. Never remove an outline without replacing it with something equally obvious.

Learned the hard way

Six things that broke

Each of these cost real debugging time on the report. None are obvious.

1. [hidden] loses to any display rule

A element marked hidden stayed on screen because a class set display: grid. Put [hidden] { display: none !important; } in the reset and never think about it again.

2. minmax(430px, 1fr) does not shrink

A card grid using minmax(430px, 1fr) pushed the whole report off every phone, because minmax will not go below its floor. Use minmax(min(430px, 100%), 1fr).

3. text-wrap: balance leaves short lines

Balance evens line lengths, which looks deliberate on a big centred headline and looks like wasted space on a left-aligned heading in a card. Those were using 58 to 69 percent of the width. text-wrap: pretty fills the line and only prevents a one-word last line.

4. A custom property set once never changes

The score rings never changed colour. .ring { --tone: var(--warn) } was set, and the .tone-good and .tone-bad classes existed but nothing ever redefined the variable. Declaring a token is not the same as reading it.

5. A centred modal covers the thing it is selling

The unlock dialog sat over the two scores on a 1366 by 768 laptop, which left nothing to unlock for. It became a bottom sheet under 820px of height, with no dark scrim, so the scores stay readable behind it.

6. Safari and Firefox trim the referrer

Both send only the origin on cross-origin requests, so a Google Maps key restricted to a subpath returns 403 on every iPhone. meta referrer and referrerPolicy are both ignored. The key restriction has to include the bare origin with a wildcard.

For the rebuild

Checklist

Copy the token block from page two verbatim. Do not re-pick the orange.

Load Plus Jakarta Sans 400 to 800 with a real fallback stack, and use it for everything.

One card style, one radius, one shadow. If a second card style appears, one of them is wrong.

Headings on clamp, body on rem. No fixed pixel type outside labels.

Orange only on actions. Green, amber and red only on verdicts.

Design at 390px first, then check 1280. Not the other way round.

Visible :focus-visible outline on every interactive element.

Every grid minmax uses min(px, 100%) as its floor.

Put [hidden] { display: none !important } in the reset.

The logo goes home, and there is a second visible way back.

Any Google Maps key is restricted to the bare origin with a wildcard, or half your mobile traffic gets a 403.

If in doubt

The report works because it shows its working and refuses to claim anything it has not measured. Carry that across and the visual details matter much less than they look like they do.
